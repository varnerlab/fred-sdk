fred/series

The fred/series endpoint returns the title, units, frequency, and date range of one series, such as "GNPCA", the real gross national product.

model = MyFredSeriesEndpointModel(apikey = apikey, series_id = "GNPCA");
request_url = url(baseurl, model);
table = api(MyFredSeriesEndpointModel, request_url; handler = process_series_response_dataframe);
FredAPI.MyFredSeriesEndpointModel — Type
mutable struct MyFredSeriesEndpointModel <: AbstractFredEndpointModel

Endpoint model for the FRED fred/series endpoint, described at https://fred.stlouisfed.org/docs/api/fred/series.html. This endpoint returns the description of one economic data series: its title, units, frequency, seasonal adjustment, and date range. Every field is at its empty value by default. A field at its empty value ("" or 0) stays out of the URL, so FRED applies its own default for that field.

Fields

  • apikey::String: the FRED API key of the client, a 32 character string of lowercase letters and digits.
  • series_id::String: the identifier of the series, e.g., "GNPCA". FRED requires this field.
  • realtime_start::String: the first day of the real-time period, written as "YYYY-MM-DD". The real-time period selects the vintage of the data that we see, i.e., the data as it stood on those days. When the field is empty, FRED uses today's date.
  • realtime_end::String: the last day of the real-time period, written as "YYYY-MM-DD". When the field is empty, FRED uses today's date.

Constructors

  • MyFredSeriesEndpointModel(; apikey::String = "", series_id::String = "", realtime_start::String = "", realtime_end::String = ""): returns a new MyFredSeriesEndpointModel instance. Every argument is a keyword argument.
source
FredAPI.url — Method
url(base::String, model::MyFredSeriesEndpointModel) -> String

Build the URL string for the fred/series endpoint of the FRED API. An HTTP GET call to this URL calls the endpoint with the parameters that the model holds. This endpoint returns the description of one economic data series: its title, units, frequency, seasonal adjustment, and date range. The URL lists the parameters in the order of the fields of the model, then the API key, then file_type=json, which asks FRED for JSON text. A field at its empty value stays out of the URL.

Arguments

  • base::String: the base URL of the FRED API, i.e., "https://api.stlouisfed.org".
  • model::MyFredSeriesEndpointModel: the endpoint model that holds the API key and the parameters of the call.

Returns

  • String: the complete URL string. The URL holds the API key, so do not print it or share it.

Throws

  • This function does not throw an error.

Example

model = MyFredSeriesEndpointModel(apikey = apikey, series_id = "GNPCA");
request_url = url("https://api.stlouisfed.org", model);

fred/series/observations

The fred/series/observations endpoint returns the observations of one series, such as the daily Henry Hub natural gas spot price, "DHHNGSP", from 2025-01-01 to 2025-01-10. FRED has no price for the holiday 2025-01-01, so FRED sends the value "." for that date, and the table handler stores missing.

model = MyFredSeriesObservationsEndpointModel(apikey = apikey, series_id = "DHHNGSP",
    observation_start = "2025-01-01", observation_end = "2025-01-10");
request_url = url(baseurl, model);
table = api(MyFredSeriesObservationsEndpointModel, request_url; handler = process_observations_response_dataframe);
FredAPI.MyFredSeriesObservationsEndpointModel — Type
mutable struct MyFredSeriesObservationsEndpointModel <: AbstractFredEndpointModel

Endpoint model for the FRED fred/series/observations endpoint, described at https://fred.stlouisfed.org/docs/api/fred/series_observations.html. This endpoint returns the observations (the data values) of one economic data series. Every field is at its empty value by default. A field at its empty value ("" or 0) stays out of the URL, so FRED applies its own default for that field.

Fields

  • apikey::String: the FRED API key of the client, a 32 character string of lowercase letters and digits.
  • series_id::String: the identifier of the series, e.g., "DHHNGSP". FRED requires this field.
  • realtime_start::String: the first day of the real-time period, written as "YYYY-MM-DD". The real-time period selects the vintage of the data that we see, i.e., the data as it stood on those days. When the field is empty, FRED uses today's date.
  • realtime_end::String: the last day of the real-time period, written as "YYYY-MM-DD". When the field is empty, FRED uses today's date.
  • limit::Int64: the largest number of observations to return, between 1 and 100000. When the field is 0, FRED uses 100000.
  • offset::Int64: the number of results to skip, starting at 0. When the field is 0, FRED skips none.
  • sort_order::String: the order of the observations by observation date: "asc" (ascending) or "desc" (descending). When the field is empty, FRED uses "asc".
  • observation_start::String: the first observation date that we want, written as "YYYY-MM-DD". When the field is empty, FRED uses "1776-07-04", the earliest date that FRED allows.
  • observation_end::String: the last observation date that we want, written as "YYYY-MM-DD". When the field is empty, FRED uses "9999-12-31", the latest date that FRED allows.
  • units::String: the transformation that FRED applies to the observations: "lin" (levels, no transformation), "chg" (change), "ch1" (change from a year ago), "pch" (percent change), "pc1" (percent change from a year ago), "pca" (compounded annual rate of change), "cch" (continuously compounded rate of change), "cca" (continuously compounded annual rate of change), or "log" (natural log). When the field is empty, FRED uses "lin".
  • frequency::String: the frequency of the observations that FRED returns: "d" (daily), "w" (weekly), "bw" (biweekly), "m" (monthly), "q" (quarterly), "sa" (semiannual), or "a" (annual). FRED also accepts the weekly variants, e.g., "wef" (weekly, ending Friday). FRED aggregates the observations to a lower frequency using the aggregation_method field, and returns an error when the frequency is higher than the frequency of the series. When the field is empty, FRED returns the observations at the frequency of the series.
  • aggregation_method::String: the way that FRED combines the observations when it lowers the frequency: "avg" (average), "sum" (sum), or "eop" (end of period). FRED uses this field only when frequency is set. When the field is empty, FRED uses "avg".
  • output_type::Int64: the layout of the observations: 1 (the observations for each real-time period), 2 (all the observations for each vintage date), 3 (the new and the revised observations for each vintage date), or 4 (the initial release of the observations only). When the field is 0, FRED uses 1.
  • vintage_dates::String: the vintage dates to return, written as comma-separated "YYYY-MM-DD" dates, e.g., "2024-01-01,2024-06-01". FRED uses these dates in place of realtime_start and realtime_end. When the field is empty, FRED does not select by vintage date.

Constructors

  • MyFredSeriesObservationsEndpointModel(; apikey::String = "", series_id::String = "", realtime_start::String = "", realtime_end::String = "", limit::Int64 = 0, offset::Int64 = 0, sort_order::String = "", observation_start::String = "", observation_end::String = "", units::String = "", frequency::String = "", aggregation_method::String = "", output_type::Int64 = 0, vintage_dates::String = ""): returns a new MyFredSeriesObservationsEndpointModel instance. Every argument is a keyword argument.

FredAPI.MyFredSeriesSearchEndpointModel — Type
mutable struct MyFredSeriesSearchEndpointModel <: AbstractFredEndpointModel

Endpoint model for the FRED fred/series/search endpoint, described at https://fred.stlouisfed.org/docs/api/fred/series_search.html. This endpoint returns the economic data series that match a search text. Every field is at its empty value by default. A field at its empty value ("" or 0) stays out of the URL, so FRED applies its own default for that field.

Fields

  • apikey::String: the FRED API key of the client, a 32 character string of lowercase letters and digits.
  • search_text::String: the words to search for, e.g., "natural gas". FRED requires this field. The search text can hold spaces and other characters, because url encodes them.
  • search_type::String: what the search text matches: "full_text" or "series_id" (the series identifiers). When the field is empty, FRED uses "full_text".
  • realtime_start::String: the first day of the real-time period, written as "YYYY-MM-DD". The real-time period selects the vintage of the data that we see, i.e., the data as it stood on those days. When the field is empty, FRED uses today's date.
  • realtime_end::String: the last day of the real-time period, written as "YYYY-MM-DD". When the field is empty, FRED uses today's date.
  • limit::Int64: the largest number of series to return, between 1 and 1000. When the field is 0, FRED uses 1000.
  • offset::Int64: the number of results to skip, starting at 0. When the field is 0, FRED skips none.
  • order_by::String: the attribute to sort the results by: "search_rank", "series_id", "title", "units", "frequency", "seasonal_adjustment", "realtime_start", "realtime_end", "last_updated", "observation_start", "observation_end", "popularity", or "group_popularity". When the field is empty, FRED uses "search_rank" when search_type is "full_text" and "series_id" when search_type is "series_id".
  • sort_order::String: the order of the results: "asc" (ascending) or "desc" (descending). When the field is empty, FRED uses "desc" if order_by is "search_rank" or "popularity", and "asc" otherwise.
  • filter_variable::String: the attribute of a series to filter the results by: "frequency", "units", or "seasonal_adjustment". Set this field together with filter_value. When the field is empty, FRED does not filter.
  • filter_value::String: the value of the filter_variable attribute to keep, e.g., "Monthly" for the frequency or "Percent" for the units. Set this field together with filter_variable. When the field is empty, FRED does not filter.
  • tag_names::String: the tag names that a series must all have, separated by semicolons, e.g., "30-year;frb". When the field is empty, FRED does not select by tag.
  • exclude_tag_names::String: the tag names that a series must not have, separated by semicolons. Set this field together with tag_names. When the field is empty, FRED does not exclude by tag.

mutable struct MyFredSeriesTagsEndpointModel <: AbstractFredEndpointModel

Endpoint model for the FRED fred/series/tags endpoint, described at https://fred.stlouisfed.org/docs/api/fred/series_tags.html. This endpoint returns the tags of one economic data series. Every field is at its empty value by default. A field at its empty value ("" or 0) stays out of the URL, so FRED applies its own default for that field.

Fields

  • apikey::String: the FRED API key of the client, a 32 character string of lowercase letters and digits.
  • series_id::String: the identifier of the series, e.g., "STLFSI". FRED requires this field.
  • realtime_start::String: the first day of the real-time period, written as "YYYY-MM-DD". The real-time period selects the vintage of the data that we see, i.e., the data as it stood on those days. When the field is empty, FRED uses today's date.
  • realtime_end::String: the last day of the real-time period, written as "YYYY-MM-DD". When the field is empty, FRED uses today's date.
  • order_by::String: the attribute to sort the results by: "series_count", "popularity", "created", "name", or "group_id". When the field is empty, FRED uses "series_count".
  • sort_order::String: the order of the results: "asc" (ascending) or "desc" (descending). When the field is empty, FRED uses "asc".

Endpoint model for the FRED fred/series/updates endpoint, described at https://fred.stlouisfed.org/docs/api/fred/series_updates.html. This endpoint returns the economic data series, sorted by the time that FRED last updated them, most recent first. Every field is at its empty value by default. A field at its empty value ("" or 0) stays out of the URL, so FRED applies its own default for that field.

Fields

  • apikey::String: the FRED API key of the client, a 32 character string of lowercase letters and digits.
  • realtime_start::String: the first day of the real-time period, written as "YYYY-MM-DD". The real-time period selects the vintage of the data that we see, i.e., the data as it stood on those days. When the field is empty, FRED uses today's date.
  • realtime_end::String: the last day of the real-time period, written as "YYYY-MM-DD". When the field is empty, FRED uses today's date.
  • limit::Int64: the largest number of series to return, between 1 and 1000. When the field is 0, FRED uses 1000.
  • offset::Int64: the number of results to skip, starting at 0. When the field is 0, FRED skips none.
  • filter_value::String: the kind of series to return: "macro" (macroeconomic series), "regional" (regional series), or "all". When the field is empty, FRED uses "all".
  • start_time::String: the start of the time window for the last update of a series, written as "YYYYMMDDHhmm" (year, month, day, hour, minute). FRED requires end_time when this field is set. When the field is empty, FRED does not filter by time.
  • end_time::String: the end of the time window for the last update of a series, written as "YYYYMMDDHhmm" (year, month, day, hour, minute). FRED requires start_time when this field is set. When the field is empty, FRED does not filter by time.
