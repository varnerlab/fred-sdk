Version 2

FredAPI calls one endpoint of version 2 of the FRED API, fred/v2/release/observations. Version 2 uses the same four steps as version 1, with two differences:

  • Version 2 reads the API key from the Authorization: Bearer header of the request, not from the URL. url puts the key in the URL, as in version 1, and api moves the key from the URL into the header.
  • Version 2 moves to the next page of results with the next_cursor value of the previous response, in place of offset. The Paging page shows how to follow next_cursor.

fred/v2/release/observations

The fred/v2/release/observations endpoint returns the observations of every series in one release. In version 2, limit caps the total number of observations across all series of the release. The example asks for the first 500 observations of release 52, the Z.1 Financial Accounts of the United States.

model = MyFredV2ReleaseObservationsEndpointModel(apikey = apikey, release_id = 52, limit = 500);
request_url = url(baseurl, model);
table = api(MyFredV2ReleaseObservationsEndpointModel, request_url; handler = process_release_observations_response_dataframe);
FredAPI.MyFredV2ReleaseObservationsEndpointModel — Type
mutable struct MyFredV2ReleaseObservationsEndpointModel <: AbstractFredEndpointModel

Endpoint model for the FRED fred/v2/release/observations endpoint, described at https://fred.stlouisfed.org/docs/api/fred/v2/release_observations.html. This endpoint returns the observations of every series in one release, in pages. FRED version 2 reads the API key from the Authorization: Bearer header, so the api function moves the key from the URL into that header. Every field is at its empty value by default. A field at its empty value ("", 0, or false) stays out of the URL, so FRED applies its own default for that field.

Fields

  • apikey::String: the FRED API key of the client, a 32 character string of lowercase letters and digits.
  • release_id::Int64: the identifier of the release. FRED requires this field.
  • limit::Int64: the largest number of observations to return, between 1 and 500000. When the field is 0, FRED uses 500000.
  • next_cursor::String: the next_cursor value of the previous response, which selects the next page of observations. Leave the field empty on the first request.

Constructors

  • MyFredV2ReleaseObservationsEndpointModel(; apikey::String = "", release_id::Int64 = 0, limit::Int64 = 0, next_cursor::String = ""): returns a new MyFredV2ReleaseObservationsEndpointModel instance. Every argument is a keyword argument.

FredAPI.url — Method
url(base::String, model::MyFredV2ReleaseObservationsEndpointModel) -> String

Build the URL string for the fred/v2/release/observations endpoint of the FRED API. An HTTP GET call to this URL calls the endpoint with the parameters that the model holds. This endpoint returns the observations of every series in one release, in pages. The URL lists the parameters in the order of the fields of the model, then the API key, then format=json, which asks FRED for JSON text. Version 2 uses format in place of file_type. A field at its empty value stays out of the URL. FRED version 2 reads the API key from the Authorization: Bearer header, so the api function moves the key from the URL into that header before it sends the request.

Arguments

  • base::String: the base URL of the FRED API, i.e., "https://api.stlouisfed.org".
  • model::MyFredV2ReleaseObservationsEndpointModel: the endpoint model that holds the API key and the parameters of the call.

Returns

  • String: the complete URL string. The URL holds the API key, so do not print it or share it.

Throws

  • This function does not throw an error.

Example

model = MyFredV2ReleaseObservationsEndpointModel(apikey = apikey, release_id = 52, limit = 10);
request_url = url("https://api.stlouisfed.org", model);
