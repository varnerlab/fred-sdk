fred/category

The fred/category endpoint returns the name and the parent category of one category, such as category 125, Trade Balance.

model = MyFredCategoryEndpointModel(apikey = apikey, category_id = 125);
request_url = url(baseurl, model);
table = api(MyFredCategoryEndpointModel, request_url; handler = process_categories_response_dataframe);
FredAPI.MyFredCategoryEndpointModel — Type
mutable struct MyFredCategoryEndpointModel <: AbstractFredEndpointModel

Endpoint model for the FRED fred/category endpoint, described at https://fred.stlouisfed.org/docs/api/fred/category.html. This endpoint returns one category: its identifier, name, and parent category. Every field is at its empty value by default. A field at its empty value ("" or 0) stays out of the URL, so FRED applies its own default for that field.

Fields

  • apikey::String: the FRED API key of the client, a 32 character string of lowercase letters and digits.
  • category_id::Int64: the identifier of the category, e.g., 125. 0 is the root category of FRED. When the field is 0, FRED uses the root category, so leaving the field out gives the same result.

Constructors

  • MyFredCategoryEndpointModel(; apikey::String = "", category_id::Int64 = 0): returns a new MyFredCategoryEndpointModel instance. Every argument is a keyword argument.
source
FredAPI.url — Method
url(base::String, model::MyFredCategoryEndpointModel) -> String

Build the URL string for the fred/category endpoint of the FRED API. An HTTP GET call to this URL calls the endpoint with the parameters that the model holds. This endpoint returns one category: its identifier, name, and parent category. The URL lists the parameters in the order of the fields of the model, then the API key, then file_type=json, which asks FRED for JSON text. A field at its empty value stays out of the URL.

Arguments

  • base::String: the base URL of the FRED API, i.e., "https://api.stlouisfed.org".
  • model::MyFredCategoryEndpointModel: the endpoint model that holds the API key and the parameters of the call.

Returns

  • String: the complete URL string. The URL holds the API key, so do not print it or share it.

Throws

  • This function does not throw an error.

Example

model = MyFredCategoryEndpointModel(apikey = apikey, category_id = 125);
request_url = url("https://api.stlouisfed.org", model);

FredAPI.MyFredCategorySeriesEndpointModel — Type
mutable struct MyFredCategorySeriesEndpointModel <: AbstractFredEndpointModel

Endpoint model for the FRED fred/category/series endpoint, described at https://fred.stlouisfed.org/docs/api/fred/category_series.html. This endpoint returns the economic data series that belong to one category. Every field is at its empty value by default. A field at its empty value ("" or 0) stays out of the URL, so FRED applies its own default for that field.

Fields

  • apikey::String: the FRED API key of the client, a 32 character string of lowercase letters and digits.
  • category_id::Int64: the identifier of the category, e.g., 125. FRED requires this field.
  • realtime_start::String: the first day of the real-time period, written as "YYYY-MM-DD". The real-time period selects the vintage of the data that we see, i.e., the data as it stood on those days. When the field is empty, FRED uses today's date.
  • realtime_end::String: the last day of the real-time period, written as "YYYY-MM-DD". When the field is empty, FRED uses today's date.
  • limit::Int64: the largest number of series to return, between 1 and 1000. When the field is 0, FRED uses 1000.
  • offset::Int64: the number of results to skip, starting at 0. When the field is 0, FRED skips none.
  • order_by::String: the attribute to sort the results by: "series_id", "title", "units", "frequency", "seasonal_adjustment", "realtime_start", "realtime_end", "last_updated", "observation_start", "observation_end", "popularity", or "group_popularity". When the field is empty, FRED uses "series_id".
  • sort_order::String: the order of the results: "asc" (ascending) or "desc" (descending). When the field is empty, FRED uses "asc".
  • filter_variable::String: the attribute of a series to filter the results by: "frequency", "units", or "seasonal_adjustment". Set this field together with filter_value. When the field is empty, FRED does not filter.
  • filter_value::String: the value of the filter_variable attribute to keep, e.g., "Monthly" for the frequency or "Percent" for the units. Set this field together with filter_variable. When the field is empty, FRED does not filter.
  • tag_names::String: the tag names that a series must all have, separated by semicolons, e.g., "income;bea". When the field is empty, FRED does not select by tag.
  • exclude_tag_names::String: the tag names that a series must not have, separated by semicolons. Set this field together with tag_names. When the field is empty, FRED does not exclude by tag.

Constructors

  • MyFredCategorySeriesEndpointModel(; apikey::String = "", category_id::Int64 = 0, realtime_start::String = "", realtime_end::String = "", limit::Int64 = 0, offset::Int64 = 0, order_by::String = "", sort_order::String = "", filter_variable::String = "", filter_value::String = "", tag_names::String = "", exclude_tag_names::String = ""): returns a new MyFredCategorySeriesEndpointModel instance. Every argument is a keyword argument.

FredAPI.MyFredCategoryTagsEndpointModel — Type
mutable struct MyFredCategoryTagsEndpointModel <: AbstractFredEndpointModel

Endpoint model for the FRED fred/category/tags endpoint, described at https://fred.stlouisfed.org/docs/api/fred/category_tags.html. This endpoint returns the tags of the series that belong to one category. Every field is at its empty value by default. A field at its empty value ("" or 0) stays out of the URL, so FRED applies its own default for that field.

Fields

  • apikey::String: the FRED API key of the client, a 32 character string of lowercase letters and digits.
  • category_id::Int64: the identifier of the category, e.g., 125. FRED requires this field.
  • realtime_start::String: the first day of the real-time period, written as "YYYY-MM-DD". The real-time period selects the vintage of the data that we see, i.e., the data as it stood on those days. When the field is empty, FRED uses today's date.
  • realtime_end::String: the last day of the real-time period, written as "YYYY-MM-DD". When the field is empty, FRED uses today's date.
  • tag_names::String: the tag names that a series must all have, separated by semicolons, e.g., "income;bea". When the field is empty, FRED does not select by tag.
  • tag_group_id::String: the group of tags to return: "freq" (frequency), "gen" (general or concept), "geo" (geography), "geot" (geography type), "rls" (release), "seas" (seasonal adjustment), or "src" (source). When the field is empty, FRED returns the tags of every group.
  • search_text::String: the words to match against the tag names and the tag notes. When the field is empty, FRED does not filter the tags by text.
  • limit::Int64: the largest number of tags to return, between 1 and 1000. When the field is 0, FRED uses 1000.
  • offset::Int64: the number of results to skip, starting at 0. When the field is 0, FRED skips none.
  • order_by::String: the attribute to sort the results by: "series_count", "popularity", "created", "name", or "group_id". When the field is empty, FRED uses "series_count".
  • sort_order::String: the order of the results: "asc" (ascending) or "desc" (descending). When the field is empty, FRED uses "asc".

Constructors

fred/category/related_tags

The fred/category/related_tags endpoint selects the series in one category that carry every tag in tag_names, and returns the other tags of those series.
